# إنشاء إصدار وتوقيعه

## أرقام الإصدارات

عدّل القيمتين في `app/build.gradle.kts` مع كل إصدار:

- `versionName`: اسم الإصدار المقروء، مثل `2.3.2`.
- `versionCode`: عدد صحيح يزداد مع كل APK يُوزّع كتحديث.

لا تغيّر `applicationId` (`com.portablefileserver`) إلا بقرار منتج واضح؛ تغييره يجعل Android يتعامل مع التطبيق كتطبيق مختلف.

## بناء الاختبار

يتطلب البناء JDK 17 وAndroid SDK Platform 34. نفّذ من جذر المشروع:

```sh
gradle :app:assembleDebug
```

الناتج `app/build/outputs/apk/debug/app-debug.apk` يستخدم مفتاح debug محلياً. GitHub Actions يبني هذا النوع ويرفعه كـ artifact؛ ليس إصداراً صالحاً للنشر لمجرد نجاح CI.

## بناء إصدار موقّع

1. استخدم مفتاح التوقيع الأصلي للتطبيق إذا كان المطلوب تحديث تثبيت قائم. لا يمكن لمفتاح debug بديل تحديث APK موقّع بشهادة مختلفة.
2. احتفظ بملف keystore وكلمات مروره خارج Git، مثل GitHub Actions Secrets أو مدير أسرار موثوق.
3. أضف إعداد signing محلياً أو workflow منفصلاً يستخدم الأسرار دون طباعتها في السجل. لا تضع القيم السرية داخل ملفات Gradle أو الوثائق أو APK.
4. ابنِ variant `release`، ثم تحقق من الشهادة والتوقيع باستخدام Android SDK Build Tools.
5. ثبّت APK على جهاز اختباري وكرّر قائمة `docs/TESTING.md` قبل التوزيع.
6. وثّق تغييرات الإصدار ونتائج الاختبار وملاحظات التوافق. لا تنشر مفتاح التوقيع أو debug APK كتحديث رسمي.

لم يُرفق مفتاح إصدار مع المصدر الحالي؛ لذلك لا يمكن من هذه الملفات وحدها إنتاج تحديث موقّع بشهادة المطوّر الأصلية.
